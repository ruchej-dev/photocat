## Критерии приёмки

1. `verify <a> <b>`: только в A/B, разный размер, разное содержимое, совпало; при разных размерах
   sha256 не считается — да (`compare` не вызывает `hash` для таких пар, тест).
2. Прогресс в stderr, `--jobs N`, `Ctrl-C` безопасен (только чтение); коды 0/1/2 — да.
3. `manifest [DIR] --out FILE`: относительные пути, экранирование, все обычные файлы, stdout без
   `--out`, неполный слепок не пишется — да.
4. `verify --manifest FILE DIR`: отсутствующие, лишние, изменённые — да.
5. Ни удаления, ни переименования, ни правки архива; единственный новый файл — слепок по `--out`;
   симлинки пропускаются со счётчиком — да.
6. Замеры на корпусе — ниже и в `docs/ARCHITECTURE.md` §Замеры.
7. Тесты — 10 новых, всего 74.

## Ограничения

- Симлинки и особые файлы не разыменовываются и не сравниваются: для сверки нужны две настоящие
  копии, а не витрина `--symlink`.
- Hardlink в двух копиях читается дважды: ускорения по inode нет.
- В CLI прерывание — `Ctrl-C`; `Progress::cancel` готов для будущей кнопки в GUI.
- Не-UTF-8 имена в слепке теряют байты через `to_string_lossy` (ADR 0014).
- `verify` сравнивает относительные пути: переименованный файл — это «только в A» + «только в B»,
  а не «совпало под другим именем».
