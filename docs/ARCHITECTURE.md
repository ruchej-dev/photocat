# Архитектура photocat

## Слои

```
L3  main.rs ── app.rs            CLI и GUI
L2  index.rs   dupes.rs   organize.rs   verify.rs   embed.rs   ocr.rs   faces.rs
L1  db.rs
L0  derive.rs   tools.rs
```

| Слой | Знает про | Не знает про |
|---|---|---|
| L0 `derive` | файлы, `image`, `image_hasher`, `kamadak-exif`, `sha2`, `tools` | БД, UI, параллелизм |
| L0 `tools` | `std::process`, `PATH`, `anyhow` | БД, UI, декодирование |
| L1 `db` | `rusqlite`, `anyhow`, `tools` (тип настроек) | декодирование, egui |
| L2 `index` / `dupes` / `organize` / `verify` | L0/L1 + `rayon`, `walkdir`, `tools` | egui |
| L2 `embed` | L0/L1 + `ort`, `tokenizers`, `serde_json`, `tools` | egui, SQL-строки |
| L2 `ocr` | L0/L1 + `rayon`, `tools`; процесс `tesseract` | egui, SQL-строки |
| L2 `faces` | L0/L1 + `ort`, `rayon`, `image`; ONNX SCRFD и ArcFace | egui, SQL-строки |
| L3 `app` | всё ниже + `eframe`/`egui` | прямые SQL-строки, декодирование в UI-потоке |

Граница проверяется скриптом `.pi/skills/enforce-architecture/scripts/check.sh` (grep по `use
crate::`), он же запрещает вызовы `fs::remove_*` и `fs::rename` в `src/`.

## Поток индексации

```
walkdir → Vec<PathBuf> → rayon(par_iter, jobs потоков)
   по файлу: metadata → sha256 → (image: decode → dHash + превью 320) → exif → дата
        → db::FileRow ──mpsc──► поток-писатель: одна транзакция на весь прогон
```

- Один декод на файл: размеры, dHash, резкость и превью считаются из одного `DynamicImage` (`derive::analyze_image`).
- `Progress` — атомики + `Mutex<String>`; GUI и консоль читают его, не блокируя воркеров.
- Ошибка одного файла не валит прогон: счётчик `errors`, файл пропускается. Если файл удалось
  проиндексировать, но без превью/метаданных (битый JPEG, нет `ffmpeg`), он остаётся в БД, а
  счётчик ошибок всё равно растёт — иначе слепая зона была бы невидимой.

## Схема БД

```sql
files(id, path UNIQUE, size, mtime, sha256, kind, width, height,
      taken_at, taken_src, lat, lon, camera, dhash, sharpness, duration_s,
      thumb, decision, indexed_at)
tags(file_id, tag, score, source)      -- source='clip:<model_id>': 7 весов
tag_hidden(file_id, tag, hidden_at)    -- владелец убрал тег у фото
embeddings(file_id, model, sha256, dim, vec, PRIMARY KEY(file_id, model))
settings(key, value)                   -- модель, путь, лимит, пороги (дубли, теги, лица),
                                       -- потоки, языки OCR, пути к программам
ocr(file_id, sha256, lang, text, chars, created_at)   -- текст с фото; PRIMARY KEY(file_id)
ocr_fts(text)                          -- FTS5, content='ocr', content_rowid='file_id'
faces(id, file_id, sha256, x, y, w, h, score, quality, thumb,
      embedding, cluster_id, manual, created_at)
face_clusters(id, label, created_at)
face_scans(file_id, sha256, faces, created_at)       -- снимок уже просканирован
```

- `kind`: `image` | `video` | `other`.
- `taken_src`: `exif` | `filename` | `mtime` — источник даты, чтобы никогда не путать точное с
  догадкой.
- `dhash`: `u64` как `i64` (SQLite INTEGER). У видео — по кадру-обложке, `NULL` только если кадр
  не извлёкся.
- `sharpness`: дисперсия лапласиана по серому кадру или превью (≤512 px), `NULL` у старых строк до
  переиндексации и у файлов без кадра. Мера сравнительная: между файлами одного корпуса, не
  абсолютная.
- `duration_s`: длительность видео в секундах из `ffprobe`; `NULL` у фото и у видео, для которых
  `ffprobe` не сработал. Разрешение хранится с учётом поворота кадра.
- `decision`: `keep` | `drop` | `NULL` — решение владельца по группе дублей. Переживает
  перезапуск и переиндексацию; сбрасывается, только если у файла изменился `sha256`.
- `thumb`: путь относительно `~/.cache/photocat/thumbs/`, ключ — `sha256[..24]` (одинаковые файлы
  делят одно превью).
- `faces.embedding`: ArcFace-вектор 512 f32 (2 КиБ) выровненного лица; `thumb` — кроп 112 px
  в кэше, ключ `<sha256[..24]>-<номер лица>`. `manual=1` — владелец отделил лицо кнопкой «не он»;
  такие группы не пересобираются. Подмена `files.sha256` триггером стирает лица и отметку прохода.
- `faces.cluster_id`: группа; `face_clusters.label` — имя, поставленное вручную. Непустая подпись
  тоже закрепляет группу при пересборке.
- `ocr.text`: текст с фото из `tesseract`. Одна строка на файл, `sha256` — содержимое на момент
  распознавания; триггер `invalidate_ocr_after_sha_change` стирает текст, если файл подменили.
  `ocr_fts` — FTS5 (`tokenize='unicode61'`), синхронизируется триггерами на `ocr`.
- `embeddings.vec`: f32 little-endian, 512 чисел (2 КиБ на фото); `sha256` — содержимое файла на
  момент расчёта. Если `files.sha256` меняется, триггер `invalidate_clip_after_sha_change` удаляет
  векторы и CLIP-теги этого файла; остальные теги не трогаются.
- `tags.score`: косинус «фото ↔ промпт». Хранятся все 7 весов; уверенным считается только первый,
  если он ≥ 0.22 и опережает второй на 0.01 (`embed::confident_tag`).

Изменение схемы — только через `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE` в `db::init`, данные
сохраняются. У схемы есть `PRAGMA user_version` (`db::SCHEMA_VERSION`): пока версия совпадает,
`open` не выполняет ни одной записи. Это важно не для красоты — иначе каждый `open` (выбор файла,
`stats`, поиск) пытался бы взять блокировку записи и ждал долгий прогон: до этой правки чтение
во время OCR висело 5 с и падало с «database is locked».

## Видео

`derive::analyze_video`: `ffprobe -of json` даёт длительность, ширину и высоту; поворот из
`side_data_list`/`tags.rotate` на 90/270 меняет ширину и высоту местами. Кадр-обложка — внешний
`ffmpeg` (ADR 0010): `-ss 10%` до `-i` (быстрый seek), один кадр, `scale=320:320` с
`force_original_aspect_ratio=decrease`; если seek не дал кадра, повтор с нуля. По сохранённому
кадру считаются `dhash`, `sharpness`; превью лежит в том же кэше под `sha256[..24]`, что и фото.
Ошибка `ffmpeg`/`ffprobe` — мягкая: строка попадает в БД без превью, счётчик `errors` растёт.
Консольное окно на Windows подавляется (`CREATE_NO_WINDOW`), на Unix — обычный `Command`.

## Дубли

1. Точные: `sha256` + размер → union-find.
2. Похожие: попарное сравнение `dhash` (`hamming ≤ max_dist`), тоже union-find.
3. Группа = компонента связности. `reason`: «точная копия», если у всех одинаковый sha256, иначе
   «похожий снимок». `waste = сумма размеров − размер самого большого`.
4. Совет `Group::suggested`: максимум резкости → разрешения → размера файла; `advice` — почему,
   словами («резче остальных на 13% · крупнее файл»). Точные копии совета не получают.
5. Решение владельца (`files.decision`) перекрывает совет: `dupes::keep_of`, `summary` (сколько
   помечено и сколько освободится), `plan_csv` (экспорт без удаления). `dupes` как CLI пишет
   только файлы отчёта и **не меняет** решения в БД — это делает GUI.

Сложность O(n²) по числу изображений с dHash: 1972 файла → 1.9 млн сравнений → 0.03 с. До 20 тыс.
фото это ~200 млн (≈3 с) — приемлемо; выше — BK-tree по 64-битным хешам (задача на будущее).

## CLIP: эмбеддинги, теги, поиск

```
превью/кадр 320 → центр-кроп → 224×224 → CLIP ViT-B/32 (int8 ONNX) → 512 f32 → normalize
текст: выбранная модель → вектор 512 → cosine по всем векторам → топ-N в сетке
```

**Каталог моделей** (`embed::catalog`) — данные, а не константа в коде:

| id | dir | размер | текстовая башня | запросы |
|---|---|---|---|---|
| `clip-vit-b32-multilingual` | `clip-vit-b32` | 217.5 МиБ | DistilBERT-multilingual + Dense 768→512 | русский и другие языки |
| `clip-vit-b32-en` | `clip-vit-b32-en` | 148.6 МиБ | CLIP text tower, выход `text_embeds` | только английский; теги остаются русскими подписями |

У обеих моделей общая зрительная башня (`Xenova/clip-vit-base-patch32`, int8) и одинаковое
пространство 512. Размер, sha256 и URL каждого файла закреплены в каталоге. `TextKind` решает,
читать ли `last_hidden_state` + проекцию или сразу `text_embeds`.

**Путь и лимит.** `settings.models_dir` (по умолчанию `<кэш>/photocat/models`), `max_model_mb`
(по умолчанию 250). Модель кладётся в `<models_dir>/<dir>/`; старый каталог `clip-vit-b32`
сохранён, чтобы уже скачанные веса не пропали. `settings.model_id` выбирает модель; пусто —
первая из каталога.

**Загрузка.** Только по согласию (GUI: галочка + «Скачать модель»; CLI: `models download --yes`).
`embed::download_model` сначала пробует выбранную модель, затем совместимые из каталога в пределах
лимита, для каждого файла — основной адрес HuggingFace и зеркало `hf-mirror.com`. Скачивание —
процесс `curl` с проверкой sha256 после каждого файла (ADR 0015, 0016). Наружу уходит только GET за
весами; ни фото, ни пути, ни запросы не отправляются.

- Модель: **зрительная часть** `Xenova/clip-vit-base-patch32` (`vision_model_quantized.onnx`),
  **текстовая** — `sentence-transformers/clip-ViT-B-32-multilingual-v1`
  (`model_quint8_avx2.onnx`, mean pooling + `2_Dense` 768→512 из safetensors). Русский запрос
  кодируется мультиязычным текстовым энкодером и сравнивается с образом в общем 512-мерном
  пространстве.
- Один декод на файл: `derive::clip_input` читает превью/кадр из кэша, нормализует каналы CLIP.
  Инференс батчами по 8; ошибка батча откатывается на поштучную обработку.
- `embed` считает **и фото, и видео** (по кадру-обложке M4): 2229 файлов корпуса, 77.3 с.
- Повторный `embed` не пересчитывает неизменённые файлы: ключ — `sha256` + `model`.
- Теги: 7 промптов на языке модели (русские для multilingual, английские для `-en`), подписи
  всегда русские. Скрытые владельцем теги в выборку не попадают.
- Поиск: текст → вектор → косинус по всем векторам выбранной модели → топ-200.
- Кластеры: k-means++ (детерминированный seed) по нормализованным векторам, k=30, 30 итераций;
  отчёт `plan/M3-clusters.md` — 12 примеров на кластер. Отчёт локальный, в git не попадает.

## Лица: SCRFD + ArcFace

```
снимок → EXIF-поворот → SCRFD 640×640 (letterbox) → рамки + 5 точек
       → подобие по 5 точкам → выровненный кроп 112×112 → ArcFace → 512 f32 → normalize
       → косинус ≥ порога → union-find → группы; подпись и «не он» живут в БД
```

**Модели.** `immich-app/buffalo_l`: `detection/model.onnx` (SCRFD, 16.9 МиБ) и
`recognition/model.onnx` (ArcFace, 174.4 МиБ), всего 182.4 МиБ. Лежат в
`<models_dir>/faces/`, URL и sha256 закреплены в `faces::FILES`, скачивание — только по согласию
через общий загрузчик `embed::download_files` (`curl`, зеркало, проверка каждого файла).
По умолчанию действует тот же лимит `settings.max_model_mb` (250 МиБ); если он меньше 182.4 МиБ,
загрузка отказывает с числами. Инференс — локальный `ort`, сеть для него не нужна.

**Детекция.** Кадр поворачивается по EXIF (`derive::load_oriented`), вписывается в 640×640 с
чёрными полями. Три головы SCRFD (шаги 8/16/32, по 2 anchor'а на ячейку) дают score, bbox и 5
точек; box-предикты умножаются на шаг, точки переводятся обратно в пиксели оригинала. Порог 0.5,
NMS по IoU 0.4, лица меньше 28 px отбрасываются. Ошибка одного снимка — счётчик, не остановка.

**Выравнивание и эмбеддинг.** По 5 точкам считается подобие (масштаб + поворот без отражения) к
каноническим точкам ArcFace; обратным преобразованием кадр 112×112 сэмплируется билинейно. Пиксели
RGB, `(x−127.5)/128`; ArcFace отдаёт 512 f32, вектор нормализуется. Кроп сохраняется в
`~/.cache/photocat/faces/<2>/<sha256[..24]>-<N>.jpg` — рядом с архивом ничего не пишется.

**Хранение и проход.** `faces` + `face_scans`: снимок пропускается по `sha256`, как CLIP и OCR;
пустой результат тоже запоминается, чтобы не сканировать снимок без людей повторно. Проход
параллельный (`rayon`, до 8 потоков), модель одна под `Mutex`: декодирование идёт параллельно,
инференс сериализован. «Стоп» проверяется между снимками, транзакция коммитит уже найденное.

**Кластеры.** Косинус между нормализованными векторами; union-find по порогу
`settings.face_threshold` (по умолчанию 0.45). Группы с подписью и лица с `manual=1` закреплены:
пересборка их не трогает, остальные пересобираются. «Не он» отделяет лицо в новую пустую группу,
которую можно назвать. Пустые безымянные группы удаляются. На 2498 лицах пересборка — 1.2 с.

## Текст на фото (OCR)

`photocat ocr` — отдельный проход, а не часть `index`: распознавание дорого и нужно не каждому файлу.

1. **Кандидаты.** Снимок без EXIF-камеры (скан, скриншот) и снимок, которому CLIP уверенно дал
   верхний тег «документ» или «скриншот» (пороги из настроек, скрытые теги не считаются). `--all`
   берёт все изображения, `--dry-run` печатает план без единого запуска tesseract.
2. **Вход.** Кадр декодируется нами: EXIF-поворот применяется
   (`image::DynamicImage::apply_orientation`), длинная сторона ≤ 2000 px. PNG уходит в
   `tesseract stdin stdout -l rus+eng` через трубу — временных файлов нет, оригинал только
   читается (ADR 0018).
3. **Хранение.** Текст живёт в `ocr`; FTS5 держат триггеры. Повторный проход пропускает файлы с
   тем же `sha256`; подмена содержимого стирает и текст, и его индекс.
4. **Поиск.** `db::fts_query` делает из ввода префиксные фразы (`"справ"* AND "2024"*`), кавычки
   снимают спецсимволы FTS. `snippet(...)` отдаёт фрагмент с маркерами « », по ним UI красит
   совпадение в карточке. Языки задаются настройкой `ocr_lang` (`rus+eng` по умолчанию).
5. **GUI.** Галочка «по тексту на фото» в строке поиска. Кнопка «Распознать текст» — в карточке
   файла и только для выбранного снимка (`ocr::run_files`, всегда заново). Пакетный проход —
   отдельная кнопка «Распознать документы (N)»: N — план из `ocr::plan`, виден до нажатия, чтобы
   долгий проход не начинался неожиданно. Без `tesseract` в `PATH` обе кнопки погашены.
6. **Пустой текст — тоже результат.** Из 435 кандидатов корпуса надписи нашлись у 146: остальные —
   снимки мебели и животных, куда CLIP попал тегом «документ»/«скриншот», либо просто фото без
   EXIF-камеры. Пустая строка пишется в БД, чтобы повторный проход не тратил на них время.

## Дата

Порядок: EXIF `DateTimeOriginal` → регулярка по имени (`IMG_20240517_144243`, `P_20190410_102958`,
`VID_...`, `V_...`) → `mtime`. Проверка правдоподобия: год 1990–2100, месяц 1–12, день 1–31,
часы < 24. Источник пишется в `taken_src`.

## Витрина (`organize`)

Витрина — отдельный каталог, где оригиналы не меняются: по умолчанию hardlink (0 байт),
`--copy` или `--symlink`. Без `--apply` печатается только план, примеры и счётчики.

| `--by` | Каталог файла |
|---|---|
| `day` (по умолчанию) | `<витрина>/ГГГГ/ГГГГ-ММ-ДД/` |
| `month` | `<витрина>/ГГГГ/ГГГГ-ММ/` |
| `event` | `<витрина>/ГГГГ/ГГГГ-ММ-ДД/` без GPS и `<витрина>/ГГГГ/ГГГГ-ММ-ДД/<ШШ.ШШN_ДД.ДДE>/` с GPS |

Событие = день + ячейка GPS ~1 км (два знака после запятой). Обратного геокодинга нет: названия
мест — сеть, которая разрешена только за весами моделей (ADR 0011, 0015), поэтому каталог места
называется координатами. Снимки без координат остаются в каталоге дня, рядом с подкаталогами мест.

**Имя файла.** Без `--name`/`--rename` — оригинальное. Шаблон из подстановок (ADR 0022):

| Подстановка | Значение | Пример |
|---|---|---|
| `{date}` | дата съёмки без разделителей | `20240517` |
| `{time}` | время съёмки, только цифры | `144243` |
| `{camera}` | модель камеры из EXIF, пробелы → `_` | `Xiaomi_Redmi_Note_8_Pro` |
| `{tag}` | уверенный CLIP-тег (пороги из настроек, скрытые не считаются) | `дети` |
| `{orig}` | исходное имя без расширения | `IMG_20240517_144243` |
| `{ext}` | расширение без точки; нет в шаблоне — добавляется само | `jpg` |

`--rename` — сокращение для `{date}_{time}_{orig}` (прежний формат переименования). Пробелы
становятся `_`, недопустимые символы выбрасываются, повторы и хвосты `_`/`-` убираются, длина
≤120 знаков, пустые подстановки не оставляют `__`. Коллизии в одном каталоге получают `-2`,
`-3`. Неизвестная подстановка — отказ с кодом 2 и списком допустимых.

**`--exclude-dup`** не включает файлы с `decision='drop'` (решение из дублей, ADR 0012): в плане
видно, сколько исключено и сколько снимков без даты. Теги читаются только если шаблон просит
`{tag}`.

## Сверка и слепок (`verify`, `manifest`)

Две команды для бэкапа, обе только читают архив. `verify <a> <b>` обходит два дерева и сравнивает
**относительные пути**; сначала размер, и только для файлов одинакового размера считается sha256.
Файлы разного размера не читаются вовсе — это и есть «размер → sha256 по размеру». Отчёт:
сколько всего в A и B, совпало по содержимому, разный размер, разное содержимое, только в A,
только в B, ошибки чтения; примеры путей (20, `--all` — все).

`manifest [DIR] --out FILE` пишет слепок в формате GNU `sha256sum`: `<sha256>  <относительный
путь>`, все обычные файлы, относительные пути с `/` на любой ОС. Имена с обратным слэшем,
переводом строки или возвратом каретки экранируются так же, как у `sha256sum` (`\\`, `\n`,
`\r`), поэтому слепок можно проверить и штатной утилитой. Без `--out` слепок идёт в stdout. Файл
слепка исключается из обхода, даже если лежит внутри архива; при ошибке чтения или отмене слепок
не пишется совсем — неполный слепок объявил бы непрочитанные файлы «лишними».

`verify --manifest FILE DIR` проверяет каталог по слепку: нет в каталоге, нет в слепке, изменено,
совпало. Симлинки и особые файлы не разыменовываются и попадают в счётчик «пропущено». Прогресс
печатается в stderr (сколько файлов прошло sha256), `--jobs N` задаёт потоки. Коды возврата:
0 — совпадает, 1 — расхождения/ошибки/отмена, 2 — ошибка аргументов. В CLI прерывание — `Ctrl-C`
(команда ничего не пишет, поэтому это безопасно); `Progress::cancel` уже поддержан, чтобы ту же
операцию можно было остановить из GUI.

## Долгие проходы: отмена и продолжение

Индексация, CLIP и OCR идут в фоновом потоке и держат одну транзакцию на прогон. Читать БД при
этом можно (`WAL` + `SCHEMA_VERSION`), а прервать — кнопкой «Стоп»: `Progress::cancel()` ставит
флаг, воркеры проверяют его между файлами (OCR — и внутри партии документов), уже начатый файл
доводится, транзакция коммитится, `Stats.cancelled` говорит «остановлено». Продолжение — тот же
проход заново: неизменённые `sha256` пропускаются, поэтому «Продолжить (N)» доделывает остаток.
Процесс `tesseract` запускается с `OMP_THREAD_LIMIT=1`, чтобы N воркеров не занимали все ядра и
окно не подвисало.

## Внешние программы

Приложение — один Rust-бинарник; всё, что требует C-стека, работает процессами (ADR 0019).
Путь к каждой программе — настройка (ADR 0020): пустое поле — поиск в `PATH`, непустое — запуск по
указанному пути. Поиск, запуск и подавление консольного окна на Windows собраны в `src/tools.rs`:
`derive` и `embed` просят `Tool::Ffmpeg`/`Tool::Tesseract`/`Tool::Curl`, а не имя строкой.

| Программа | Модуль работы | Настройка | Без неё |
|---|---|---|---|
| `ffmpeg` | `derive::analyze_video` | `tool_ffmpeg` | видео в индексе без превью и dHash, ошибка в счётчике |
| `ffprobe` | `derive::video_probe` | `tool_ffprobe` | видео без длительности и разрешения |
| `tesseract` | `derive::ocr_image` | `tool_tesseract` | OCR выключен (кнопка погашена, `ocr` подсказывает путь) |
| `curl` | `embed::download_model` | `tool_curl` | веса модели кладутся вручную |

**Проверка пути.** При сохранении программа запускается с флагом версии (`-version` у
ffmpeg/ffprobe, `--version` у tesseract/curl). GUI пишет итог или ошибку в статус-строку и не
сохраняет неработающий путь; CLI `settings --tesseract PATH` при ошибке завершается с кодом 2 и
ничего не пишет в БД. Пустой путь проверять нечего — программа ищется в `PATH` в момент работы.

**`doctor`** печатает для каждой программы версию, откуда взят путь (настройки или `PATH`),
найденный файл, зачем она нужна и что сломается без неё; затем языки tesseract против
`settings.ocr_lang` (`rus+eng` по умолчанию), модель CLIP и размер БД. Отсутствие программы —
состояние, а не падение: отключается только её вид работы.

## Кросс-платформенность

Цель — Linux (ADR 0014), но код не содержит тупиков: кэш ищется через `XDG_CACHE_HOME` /
`LOCALAPPDATA` / `HOME`, симлинки — с `#[cfg(unix)]` и `#[cfg(windows)]`, внешние
`ffmpeg`/`ffprobe`/`curl`/`tesseract` берутся из настроек или `PATH` (`tools::Tools`) и
запускаются без консольного окна на Windows.
Известное ограничение: не-UTF-8 имена (в Linux допустимы) теряются при записи пути в SQLite через
`to_string_lossy`; для видео, загрузки модели и OCR нужны соответствующие программы в `PATH`
(без tesseract пропадает только OCR — остальное работает). Что именно есть на машине, печатает
`photocat doctor`; пакеты ставятся штатным пакетным менеджером ОС (Arch: `tesseract` +
`tesseract-data-rus` + `tesseract-data-eng`, Windows/macOS — свои сборки ffmpeg и tesseract).
