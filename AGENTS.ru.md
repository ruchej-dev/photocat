# AGENTS.md — конституция проекта photocat

*English version: [AGENTS.md](AGENTS.md). Это русский вариант; основной язык документации — английский.*

`photocat` — нативный каталогизатор медиаархива на Rust: индексация каталога, поиск дублей и
серий, раскладка по датам, дальше — ML-теги по содержимому. Пользователь — владелец семейного
архива (65 ГБ фото и видео), а не фотограф и не администратор сервера.

Этот файл главнее привычек и главнее задачи. Если задача требует нарушить правило — спросить
владельца, а не «немного» нарушить.

## 1. Жёсткие ограничения

- **Оригиналы неприкосновенны.** Ни один код не удаляет, не переименовывает и не перемещает файлы
  архива. Допустимо только создавать новое: строки в БД, превью в кэше, ссылки в витрине.
  Единственные места, где создаются файлы в пользовательском каталоге, — `organize` и `export`
  по явному `--apply` (витрина по датам и копии альбома). Исключение, явно запрошенное владельцем: «Корзина» помечает файл в БД, а «Очистить
  корзину» после подтверждения переносит его в **системную** корзину ОС (`src/recycle.rs`).
  Безвозвратного удаления в приложении нет. Кэш (`<кэш>/photocat/`) чистит только `src/storage.rs`,
  и только после подтверждения; архив этот код не трогает.
- **Только Rust + egui/eframe.** Никакого Electron, Tauri, webview, JS/TS — ни как зависимости, ни
  как шага сборки.
- **Сеть — только за внешним функционалом и только с согласия.** Приложению разрешено скачивать
  модели и веса (HTTPS) после явного согласия владельца: кнопка в настройках и лимит размера.
  Запрещено отправлять куда-либо пользовательские данные: фото, видео, пути, имена, даты, теги,
  запросы, статистику, телеметрию. Никакой автоматической загрузки без нажатия. Всё скачанное
  проверяется по sha256 и лежит на диске; офлайн-режим остаётся рабочим.
- **Кросс-платформенность.** Целевая среда — Linux (Arch + Wayland), но код не упирается в ОС:
  кэш (`db::cache_dir`), симлинки, внешние процессы (`ffmpeg`, `ffprobe`, `curl`, `tesseract`) и
  пути имеют запасной вариант; домашние пути в коде и UI не хардкодятся. Платформенные ветки — только парой
  `#[cfg(unix)]` / `#[cfg(windows)]`, без «пока сойдёт».
- **Дорогое — в фон.** Декодирование, хеширование, инференс, кластеризация: никогда в UI-потоке;
  прогресс виден, окно не замирает, долгий проход можно остановить кнопкой «Стоп» и продолжить.
- **Тяжёлые операции сначала показывают план.** `organize` без `--apply` — dry-run; индексация
  пишет только в кэш; ML-теги сначала в отчёт.
- **Лицензия.** photocat распространяется по Apache License 2.0 (`LICENSE`, `NOTICE`). Новая
  зависимость должна быть совместима с Apache-2.0 и записана в `docs/DECISIONS.ru.md` вместе с тем,
  что было бы без неё.

## 2. Как начать сессию (порядок чтения)

Не читать код «с нуля» и не сканировать репозиторий. Дешёвый вход:

1. `plan/STATUS.ru.md` — строка `STATE:` и раздел «Дальше». Это единственный источник правды о том,
   где мы.
2. `plan/BACKLOG.ru.md` — задачи по порядку, у каждой критерий приёмки.
3. `docs/ARCHITECTURE.ru.md` — карта модулей, схема БД, инварианты (один раз за сессию).
4. Только потом — файлы, которые называет задача, и их прямые вызовы.

Если подсказка в `plan/STATUS.ru.md` или `plan/BACKLOG.ru.md` неверна — исправить её в том же изменении.
Документ, который врёт, — дефект.

Задача «продолжить проект» имеет шаблон: `/next-task` (`.pi/prompts/next-task.md`).

## 3. Карта кода

| Файл | Слой | Отвечает за | Не должен знать про |
|---|---|---|---|
| `src/i18n.rs` | L0 | язык интерфейса и отчётов CLI: `Lang`, `t(lang, текст)`, `fill(lang, шаблон, значения)`, таблица ру→англ | БД, UI, декодирование |
| `src/derive.rs` | L0 | sha256, dHash, EXIF (дата/GPS/камера), превью, дата из имени | БД, UI, индексатор |
| `src/tools.rs` | L0 | пути к `ffmpeg`/`ffprobe`/`tesseract`/`curl`, поиск в `PATH`, проверка версии | БД, UI, декодирование |
| `src/db.rs` | L1 | схема SQLite, вставка/выборка, альбомы (дерево и порядок), `Progress`, `human()` | egui, декодирование картинок |
| `src/index.rs` | L2 | обход `walkdir`, rayon-параллелизм, поток-писатель | egui |
| `src/dupes.rs` | L2 | union-find, точные и похожие дубли, CSV | egui |
| `src/embed.rs` | L2 | CLIP-эмбеддинги, теги, косинусный поиск, k-means | egui, БД-строки |
| `src/eval.rs` | L2 | размеченная проверка: воспроизводимая выборка, `labels.csv`, контактные листы, top-1/top-3 и точность уверенного тега | egui, строки SQL |
| `src/ocr.rs` | L2 | кандидаты на текст, проход `tesseract`, запись текста в БД | egui, декодирование картинок |
| `src/faces.rs` | L2 | SCRFD-детекция, выравнивание, ArcFace-эмбеддинги, кластеры лиц | egui, прямые SQL-строки |
| `src/organize.rs` | L2 | план по датам, hardlink/copy/symlink, выгрузка альбома копиями | egui |
| `src/verify.rs` | L2 | сверка двух копий, слепок sha256sum | БД-схема, egui |
| `src/recycle.rs` | L2 | перенос в системную корзину по подтверждению, очистка строк | превью, egui |
| `src/player.rs` | L2 | встроенный плеер: демукс `rff`, декод H.264/HEVC/AAC, звук `cpal`, кадр в RGBA | БД, egui |
| `src/storage.rs` | L1 | занятое место, очистка кэша и индекса | архив, egui |
| `src/app.rs` | L3 | весь GUI на egui | прямые вызовы SQL |
| `src/main.rs` | L3 | разбор CLI, подкоманды | — |

Правило одной зависимости: **модуль зависит только от нижних слоёв**. Проверяется
`bash .pi/skills/enforce-architecture/scripts/check.sh`.

## 4. Данные

- `tags`: строки `(file_id, tag, score, source)`, где `source='clip:<model_id>'`; метки и промпты —
  в `tag_defs` на модель (правит владелец). Смена `sha256` стирает CLIP-теги и вектор файла.
- БД: `~/.cache/photocat/photocat.db` (SQLite, WAL). Пересоздаётся индексацией; в каталог архива
  не пишем никогда. `files.trashed_at` — корзина приложения (файл на диске цел), `user_tags` —
  свои теги владельца. Список каталогов хранится в `settings.roots` строкой; каталог убирается
  из индекса удалением строк, не файлов. Альбомы (`albums`, `album_files`) — дерево и порядок
  файлов, тоже только строки: имя уникально среди соседей, `position` плотный, один снимок —
  одна строка в альбоме. Удаление альбома чистит только строки.
- Язык интерфейса: `settings.lang` = `en` (основной) или `ru` (второй). Выбор — в «Настройки →
  Интерфейс», применяется ко всему окну. При первом запуске (строки `lang` ещё нет) язык берётся из
  локали системы через `db::ensure_lang` (заданные `LC_ALL`/`LC_MESSAGES` решают сами, иначе
  `LANGUAGE`/`LANG`), при неопределённой локали — английский; результат сохраняется, поэтому
  позднейший выбор владельца всегда главнее.
- Превью: `~/.cache/photocat/thumbs/<2 симв.>/<sha256[..24]>.jpg`, 320 px по длинной стороне.
- Лица: кропы `~/.cache/photocat/faces/<2 симв.>/<sha256[..24]>-<N>.jpg`, 112×112;
  векторы и группы — в БД.
- Модели: по умолчанию `<кэш>/photocat/models/<id>/`, лица — `<models_dir>/faces/` (182.4 МиБ);
  путь, лимит размера и выбор модели — в настройках приложения. В каталоге четыре записи
  (`models list`): две CLIP ViT-B/32 (мультиязычная 217.5 МиБ — по умолчанию, английская 148.6 МиБ),
  SigLIP base 224 английская (203.5) и SigLIP 2 base 224 мультиязычная (393.3 — нужен лимит 400).
  Вес тега каждой модели откалиброван в шкалу CLIP, поэтому один порог значит одно и то же на
  любой модели. Загрузка — только с согласия и с проверкой sha256; `scripts/fetch-model.sh`
  остаётся ручным запасным путём для CLIP.
- Кэш на 2230 файлов: БД 1.3 МБ, превью 29 МБ; после CLIP + OCR + лиц БД ~22 МБ
  (векторы CLIP 4.4 МиБ, лица 2498 × 2 КиБ), кропы лиц ~11 МБ. Если стало в 10 раз больше —
  это регресс.
- Схема меняется только через `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE` в `db::init` с
  сохранением данных, и вместе с этим поднимается `db::SCHEMA_VERSION`: пока версия совпадает,
  `open` не пишет, поэтому чтение не блокируется долгим прогоном. Индекс на 2230 файлов стоит
  65 с, но его нельзя терять из-за правки схемы.

## 5. Команды

```bash
cargo build --release           # ~3 мин с нуля, дальше секунды
cargo run                       # dev-профиль: зависимости с opt-level 3, свой код 1 —
                                # видео играет и в `cargo run` (в чистом debug было 2.2 к/с)
cargo clippy --all-targets      # перед коммитом
bash .pi/skills/enforce-architecture/scripts/check.sh   # границы слоёв; архив не удаляется
./target/release/photocat index <каталог>    # индексация (пишет в кэш)
./target/release/photocat stats
./target/release/photocat dupes --max-dist 6
./target/release/photocat albums list --tree             # дерево альбомов (только данные)
./target/release/photocat albums new --name "Дача 2024"  # альбом; add/remove путями из индекса
./target/release/photocat export --album 1 --out DIR     # план выгрузки; --apply — копии файлов
./target/release/photocat organize --out DIR            # dry-run
./target/release/photocat verify A B                    # две копии: размер → sha256, код 0/1
./target/release/photocat manifest DIR --out file.sha256 # слепок для будущих проверок
./target/release/photocat verify --manifest file.sha256 DIR  # проверить по слепку
./target/release/photocat embed                          # CLIP-эмбеддинги и теги (локально)
./target/release/photocat embed --refresh                # пересчитать векторы (после смены входа)
./target/release/photocat embed --retag                  # только теги по сохранённым векторам
./target/release/photocat tags [--list|--add МЕТКА --prompt ТЕКСТ|--enable ID|--disable ID|--rm ID]
                                [--export FILE|--import FILE|--reset]  # словарь тегов модели
./target/release/photocat search "торт" --top 20         # смысловой поиск
./target/release/photocat faces                          # лица: детекция, эмбеддинги, группы
./target/release/photocat faces --dry-run                # сколько снимков ещё без лиц
./target/release/photocat faces --list                   # группы лиц с подписями и счётчиками
./target/release/photocat faces --recluster --threshold 0.45  # пересобрать группы
./target/release/photocat play видео.mp4                 # встроенный плеер без экрана (замер)
./target/release/photocat play видео.mp4 --decode-only   # только декод: к/с и цена кадра
./target/release/photocat faces download --yes           # веса лиц (сеть, только по согласию)
./target/release/photocat faces label --id 5 --name Лиза # подписать группу
./target/release/photocat faces split --id 123           # разъединить лицо
./target/release/photocat ocr                            # текст с документов и скриншотов (tesseract)
./target/release/photocat ocr --dry-run                  # сколько файлов пойдёт в OCR
./target/release/photocat ocr --file photo.jpg           # текст с одного снимка
./target/release/photocat search "справка" --text        # поиск по распознанному тексту
./target/release/photocat doctor                         # что есть: ffmpeg, tesseract, языки, модель
./target/release/photocat clusters --k 30                # кластеры → plan/M3-clusters.md
./target/release/photocat eval --folder DIR --out DIR     # размеченная проверка: выборка, labels.csv, листы
./target/release/photocat eval --labels DIR/labels.csv    # top-1/top-3, уверенность, процентили
./target/release/photocat models list                    # каталог моделей и что уже скачано
./target/release/photocat models download --id ID --yes  # веса (сеть, только по согласию)
./target/release/photocat settings [--lang en|ru]        # модель, путь, лимит, пороги, язык
./target/release/photocat gui                            # GUI
# веса: кнопка «Скачать модель» в «Настройках» (с согласием) или вручную:
bash scripts/fetch-model.sh
bash .pi/skills/corpus-bench/scripts/bench.sh            # замер на реальном корпусе
```

## 6. Правила изменений

- Один коммит — одна тема; сообщение по-английски, в повелительном наклонении, с сутью, а не «fix».
- Сначала обновляются документы, которые описывают поведение (`docs/`, `plan/`), потом код — в том
  же коммите.
- **Документация и коммиты — по-английски.** Русская документация остаётся вторым вариантом
  (`*.ru.md`) со ссылкой из английского основного файла; переведённый документ переименовывается,
  а не удаляется.
- **Общение с владельцем — по-русски.** Владелец читает по-русски; репозиторий говорит
  по-английски.
- **UI-строки переводятся, а не дублируются.** Русская исходная строка идёт через
  `i18n::t(lang, "…")`, английский текст добавляется в таблицу `PAIRS` в `src/i18n.rs`. Отчёт CLI
  несёт язык в поле `lang` и собирает фразу через `i18n::fill` (M21.6). Экран
  считается переведённым, только когда через `t()` идут все его подписи; непереведённые экраны
  показываются по-русски — это видимое состояние, его охват ведёт `plan/I18N.md`.
- Идентификаторы кода — по-английски. Числа с единицами в GUI — через `db::human_in(lang, n)`
  (`КиБ/МиБ` или `KiB/MiB`), в отчётах CLI — через `db::human()`.
- Новый вид/панель — по скиллу `add-view`. Новый экран — по скиллу `ui-design`.
- Не добавлять зависимость, пока не записано в `docs/DECISIONS.ru.md`, зачем она и что было бы без неё.
- Новые замеры (время, объём, число групп) — в `docs/ARCHITECTURE.ru.md` § «Замеры», с датой и
  корпусом. Числа без корпуса не значат ничего.

## 7. Как проверять

1. **Headless всегда**: `index` на тестовом корпусе, `stats`, `dupes`, `organize` (dry-run) —
   проверяют логику без единого пикселя.
2. **Корпус**: реальные 2230 файлов из `~/Documents/nasty/mail_media/Фотографии с телефона`
   (см. `corpus-bench`). Ожидаемо: индексация ~85 с (фото + обложки видео через ffmpeg), 103 группы
дублей, 238 файлов, 214 МиБ; `embed` на фото и видео ~77 с, 2229 файлов.
3. **GUI**: компиляция + короткий запуск (`timeout 6 ./target/release/photocat gui`). Открывать
   окно на экране владельца без предупреждения — только для smoke-теста и не дольше нескольких
   секунд; полноценный просмотр делает владелец.
4. Правило приёмки: изменение не готово, пока не посчитан результат на реальных данных и не
   записан в `plan/STATUS.ru.md`.

## 8. Известные ограничения (не баги, а состояние)

- Видео индексируются с кадром-обложкой, dHash, длительностью и разрешением через `ffmpeg`/`ffprobe`
  (M4). Без dHash остаётся один битый JPEG; видео в CLIP-поиске пока не участвуют.
- Порог похожести 6/64 даёт ложные срабатывания (разные фото в одной группе) — автоматически
  удалять по dHash нельзя.
- HEIC/AVIF-видео кодеков нет: `image` не читает HEIC.
- `hardlink` не работает между разными ФС (`/tmp` — tmpfs): витрину делать на том же диске или
  `--copy`/`--symlink`.
- CLIP-теги приблизительны: уверенный тег — только если первый отрывается от второго на 0.01;
  «не уверен» — нормальное состояние, а не баг. Модель требует AVX2 (int8-квантование), 218 МиБ.
  Вход — два кадра на снимок (центр-кроп + весь кадр с полями), векторы усредняются; это убирает
  «документ» из лидеров на вертикальных рендерах, но «мебель» первой сама по себе не делает.
  SigLIP 2 base 224 мультиязычная есть в каталоге, но не по умолчанию: 393.3 МиБ, 0.170 с на файл
  (CLIP 0.063) и на архиве владельца она ловит 69.0 % документов с текстом при том же уровне
  уверенности, против 85.9 % у CLIP; её русский поиск слабее мультиязычной текстовой башни CLIP
  (M15.6, ADR 0041).
- Лица (M6): SCRFD + ArcFace, порог 0.45 по умолчанию; 2498 лиц на 856 снимках корпуса за 630 с,
  617 групп. Детектор иногда находит «лицо» на экране/статуе и путает родственников — ложная
  склейка разъединяется кнопкой «не он», подпись закрепляет группу. Модель лиц 182.4 МиБ.
  OCR требует `tesseract` в `PATH` и языковые пакеты `rus`/`eng`; без него
  всё остальное работает, а кнопка «Распознать текст» погашена. Из 435 кандидатов корпуса текст
  нашёлся у 146 — снимки без надписей остаются с пустой строкой и не пересчитываются.
- `plan/M3-clusters.md` — локальный отчёт с путями архива, в git не попадает.
- Язык интерфейса: остов (навигация, верхняя панель, баннер, диалог «Настройки») переведён;
  содержимое экранов переводится по одному — см. `plan/I18N.md`.
- Корзина приложения не физическая: «Очистить корзину» переносит в системную корзину ОС через
  `trash`; очистка кэша удаляет только `<кэш>/photocat/*`. Оба действия требуют подтверждения.
- Видео играет встроенный плеер (M14, ADR 0030): H.264 и HEVC Main, AAC, звук через `cpal`;
  внешних программ не нужно. Три потока: видео, звук, показ. Звук — мастер, только пока он реально
  идёт; иначе идут настенные часы, и видео не стоит. 1080p держит реальное время (29.8 к/с при
  30 к/с источника), 2520×1080 — 22.9 к/с с опозданием до 0.5 с; 4K не играет. Кадр перед показом
  уменьшается до 1280 px. Кодеки вне области (VP9, Opus, 4:2:2) и битые файлы уходят во внешний
  `ffplay`, если он есть; иначе — системный проигрыватель.
- Повторная индексация пропускает файлы, у которых совпали путь, размер и mtime. Если содержимое
  изменили, сохранив размер и время, sha256 не пересчитается — это цена скорости.
- Выгрузка альбома не переименовывает и не удаляет уже выгруженное: после переупорядочивания
  файл остаётся под старым номером, а повторная выгрузка говорит «порядок в цели устарел N»;
  лечится ручной выгрузкой в новый каталог.
- Теги CLIP — подсказки из словаря: 14 общих меток по 2–3 шаблона по умолчанию; вес тега —
  лучший из шаблонов. Метки и промпты правятся в «Настройках → Теги» (`tag_defs` в БД на
  модель), пересчёт — `embed --retag` без повторного CLIP по фото. Свободный поиск словами
  остаётся главным способом найти предмет.
